\section{Synthesizer}

The synthesizer is the top level module of the design which takes the note data, converts it into a time base and routes it to the oscillators. Other than connecting all the individual modules (see \autoref{fig:blockdiagram}), the synth module is responsible for automatically generating an array of oscillator instances (oscillator stack) via a \emph{generate-for}, demonstrated in \autoref{fig:synth-for-generate}. This approach allows for adjusting the number of voices with a single parameter \lstinline!OSC_VOICES! in the \texttt{global.v} file. Should further optimizations be found, the parameter can be changed to increase polyphony count. This automatically opens up additional MIDI channels.

\subsection{Timebase Calculation}

The MIDI decoder yields just the note number, which can not yet be interpreted as a frequency. For this, a \acl{LUT} is implemented serving, as an interface between note number and timebase.

As seen in \autoref{eq:f-K}, the process to convert a note number to a frequency, let alone a counter value, is not a straight forward calculation to be implemented in \acs{CMOS} logic. Multiple challenges arise with this calculation, especially for divisions and modulo operations. The only convenience is, that the base of the exponential is two. For this, logical shift operations (<<,>>) will be leveraged.

Instead of performing the calculation at all, a \acl{LUT} could be created and indexed with the note number directly, which returns a counter value. With this approach, the space which is occupied just by the \acl{LUT} has to be considered. Storing all the notes over the MIDI piano note range (21-108) would require a total of 88 entries, each with the bitwidth of the oscillators resolution.

To efficiently calculate the note frequencies, a LUT is used to store the half\footnote{Only half the countervalue is needed, because the squarewave has a duty cycle of \SI{50}{\percent}. This allows to achieve one additional bit of resolution.} counter periods of only a single octave. The other notes can then be reached, by dividing (>>) or multiplying (<<) by $2$.

\subsubsection{Choosing a Clock Frequency}

To represent a time duration with a counter, a core frequency needs to be known. Only then, a time resolution can be defined, which is represented by a counter increment.

\begin{wrapfigure}[14]{r}{6cm}
	\vspace*{-16pt}
	\centering
	\includegraphics[width=6cm]{DTO.drawio.png}
	\caption{Generating custom time periods with a fixed clock cycle by defining a maximum countervalue}\label{fig:dto}
\end{wrapfigure}

From \autoref{fig:dto} can be derived, that the relation between the half period counter value $N$ and the clock frequency is given by
\begin{equation}
	N (K_\text{MIDI})= \left\lfloor\frac{f_\text{clk}}{2f_\text{note}(K_\text{MIDI})}\right\rfloor\label{eq:cnt-freq}
\end{equation}

For the lowest frequency, the largest counter value is needed. To optimally cover the whole counter range, the largest counter value is chosen as a power of two. The exponent resulting in the largest countervalue is defined as the Bitwidth of the counter. This value is chosen to be
\[
	BW = \SI{16}{\bit}
\]
With the lowest piano note being an $A_0\equiv \SI{27.5}{\hertz}$ with the note number $K=21$, the required clock frequency is calculated by
\[
	f_\text{clk} = 2f_{A_0} N_{\max} = 2\cdot \SI{27.5}{\hertz} \cdot 2^{16} \approx \SI{3.604}{\mega\hertz}
\]

To mitigate counter overflows, the clock frequency is reduced to a round value of
\begin{equation}
	f_\text{clk}=\SI{3.5}{\mega\hertz}, \quad t_{\text{clk}} = \frac{1}{f_\text{clk}} \approx \SI{285.7}{\nano\second} \label{eq:f-clk}
\end{equation}

\subsubsection{Precalculating the Octave}

As stated, only the counter values of a single octave will be stored and are shifted left or right to double or half the frequency. With this approach, a common ground is found between calculating the counter value from the note number directly and looking it up from a \acs{LUT}. The task is now to decide on one of the $\lfloor 127/12\rfloor = 10$ possible octaves in the \acs{MIDI} range. The options are:

\begin{itemize}[noitemsep]
	\item Choosing the highest octave and shift up. The highest frequencies require the smallest counter values, so this option would be the most memory efficient. But it has to be analysed, if the frequencies are precise enough not to propagate a significant error down to the lower frequencies.
	\item Choosing the lowest octave and shift down. This requires the most amount of space but eliminates the systematic error.
	\item Choosing a middle octave and shift up or down, if neither of the options above are optimal.
\end{itemize}

A deviation from the optimal note frequency occurs, because the calculated counter period in \autoref{eq:cnt-freq} can only assume integer values, while the decimal places are discarded. Higher frequencies are closer to the smallest time period to be resolved (\autoref{eq:f-clk}), which results in a higher relative error. Shifting from a smaller counter period upwards, ignores the lower significant bits (LSB), which could otherwise be used to store more precise values. E.g. shifting $N_\text{CNT}=165_d\equiv 10101010_b$ by four octaves yields:
\[
	10101010 << 4 = 10101010{\color{red}0000}\quad (\text{introduced zeros})
\]
As shifting is multiplicative, the same relative error applies to the resulting counter period directly. First, the highest MIDI octave is evaluated with \autoref{eq:cnt-freq} and \autoref{eq:f-K} using Python\footnote{\url{https://colab.research.google.com/drive/112KU6qkG-dn52oH6FUdRSUOJgx0EZzzK?usp=sharing}}. The results are shown in \autoref{tab:high-octave-dev}. For the synthesized $f_\text{synth}$, first the equivalent counter value is calculated, floored, and then re-evaluated back to the frequency:
\begin{equation}
	f_\text{synth}(K_\text{MIDI}) = \frac{f_\text{clk}}{N(K_\text{MIDI})}\cdot \frac{1}{2}\label{eq:f-synth-1}
\end{equation}

Shifting the count values from \autoref{tab:high-octave-dev} eight octaves down to the lowest piano octave (multiplying $N_\text{CNT}$ by $2^8=256$ and applying \autoref{eq:cnt-freq}), shows, that the relative error is preserved, with the results in \autoref{tab:high-to-low-octave-dev}. Here the synthesized frequency is calculated by
\begin{equation}
	f_{\text{synth}}(K_\text{MIDI}) = \frac{f_\text{clk}}{2^8 \cdot N(K_\text{MIDI}+12\cdot 8)}\cdot \frac{1}{2}
\end{equation}

If $f_\text{synth}$ for the lower frequency range is directly calculated in the same way as for the values in \autoref{tab:low-octave-dev} using \autoref{eq:f-synth-1}, it can be seen by the results in \autoref{tab:low-octave-dev}, that the relative error is reduced by factors up to $500$.

\subsubsection{Optimisations}

The oscillator module was optimized to route as few wide signals as possible and reducing the size for logic operation. For example, to reduce the size of the time base comparison, only the set of the smallest distinguishable bit indices is compared. As there are much less entries in the lookup table than variations of a 7 bit number, there must be bit-positions in each entry, which do not amount to the distiction between them.

The algorithm for this is given in Algorithm \ref{alg:subset}. With each combination of bit indices, the elements of $\vecb{v}$ at the current subset are collected into a new vector $\vecb{p}$ and then added to a set $P$ with unique elements. When the set $P$ reaches the size of the \acs{LUT}, a subset has been found. To achieve this, the \texttt{combinations}\footnote{\url{https://docs.python.org/3/library/itertools.html\#itertools.combinations}} method from the \texttt{itertools} python library is used.

\begin{algorithm}
	\caption{Extract the smallest subset of indices, to distinguish two time bases from the binary \acs{LUT} values in \autoref{tab:candidates}.}\label{alg:subset}
	\begin{algorithmic}[1]
		\Require A set of $n$ binary vectors $V = \{\vecb{v}_1, \vecb{v}_2, \dots, \vecb{v}_n\}$ of length $M$
		\Ensure A minimal subset of bit indices $S \subseteq \{0,1,\dots,M-1\}$ such that all vectors are unique on $S$
		\For{$r \gets 1$ to $M$}
		\ForAll{subsets $S \subseteq \{0,1,\dots,M-1\}$ of size $r$}
		\State $P \gets \emptyset$
		\ForAll{$\vecb{v} \in V$}
		\State $\vecb{p} \gets $ elements of $\vecb{v}$ at the indices in $S$
		\State add $\vecb{p}$ to $P$
		\EndFor
		\If{$|P| = n$}
		\State \Return $S$
		\EndIf
		\EndFor
		\EndFor
		\State \Return $\{0,1,\dots,M-1\}$ \Comment{if all bits are needed}
	\end{algorithmic}
\end{algorithm}

The set on indices returned by evaluating the \acs{LUT} with the algorithm is
\[

\]
