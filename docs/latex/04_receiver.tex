\section{Receiver}

As \acs{UART} is a common interface, there are already several implementations available in Verilog. For this project, an open source implementation \cite{ben_marshall_uart_verilog} under the MIT license was used as a starting point and has then been adjusted to the project. As the project only recieves data and does not sent any, only the \acs{UART}-receiver has to be implemented.

\subsection{Statemachine}

At the core of the receiver is a \ac{FSM} (\autoref{fig:rx-fsm}) with the four states a UART transmission can assume: \texttt{IDLE}, \texttt{START}, \texttt{RECV} and \texttt{STOP}. A combiatorial process decides, which state is registered with the next clock cycle as shown in \autoref{lst:rx-nextFsmState_p}.

\paragraph{IDLE} With each clock cycle, the input is latched in \lstinline!rxDataReg! (\autoref{lst:rx-rxBuffer_p}). The data register is normally high in the idle state. When a startbit is detected, so the \lstinline!rxDataReg! wire assumes a low state, the next state is set to \lstinline!START!.
\paragraph{START} The counter \lstinline!cycleCounter! divides the frequency into the baudrate defined in \texttt{global.v} (\autoref{lst:rx-countCycles_p}). After a bit-period has elapsed, the next state is set to \lstinline!RECV!, as the period of the start bit has now elapsed.
\paragraph{RECV} A second counter \lstinline!bitCounter! counts the number of sampled databits at the input (\autoref{lst:rx-countBit_p}). When the expected payload is recieved, the next state is set to \lstinline!STOP!.
\paragraph{STOP} The cycle counter counts the remaining half bit period and sets the next state to \lstinline!IDLE!.

]{rx.v}

To acquire the data, the input is latched into a sample register in the middle of a bit period (\autoref{lst:rx-sampleBit_p}). When the bit period has elapsed, the sampled bit is then collected in the \lstinline!midiData! byte (\autoref{lst:rx-updRxBuffer_p}), which is then assigned to the output of the module. Whenever the whole payload is received, the \lstinline!dataReady_o! strobe is pulsed (\autoref{lst:rx-dataReady_p}), which is required by the \acs{MIDI} decoder.
