\subsection{Pinout}

The project features four voices implemented as individual squarewaves oscillators. The output of each oscillator is routed to the outputpins \texttt{uo[0]}\dots\texttt{uo[3]}. Output \texttt{uo[7]} yields a PWM Signal, which encodes the number of actively running oscillators. This output may be used to control the gain of external circuitry when mixing the oscillator outputs together. The project has one input \texttt{ui[3]} to which the \acs{MIDI} signal has to be supplied to. This pin is also connected to the \acs{UART}-TX output of the RP2040 Microcrontroller, which is populated on the TinyTapeout test \acs{PCB}. The RP2040 may be used to emulate a \acs{MIDI} controller or to interface the instrument via \acs{USB}. \autoref{fig:pinout} summarises the in- and outputs of the ASIC.

\subsection{Block Diagram}

An abstract overview of the project implementation can be seen in \autoref{fig:blockdiagram}. The block-titles outside of each block repesent the Verilog module name coherent with the code-repository.

\begin{figure}[h]
    \centering
    \includegraphics[width=\textwidth]{bsb-detailed.png}
    \caption{Abstract Blockdiagram of the Synthesizer (\texttt{synth} module)}\label{fig:blockdiagram}
\end{figure}

The signal flow starts at the input, where the \acs{MIDI} messages are received via \acs{UART}. The bits of the input stream are collected into bytes, which are then fed into a \acs{MIDI} decoder. The \acs{MIDI} decoder extracts the note- and channel number and if a on or off command is received. 

The note number indexes a lookup table which returns a counterbase for the corresponding frequency. Each oscillator in the stack is listening on its own \acs{MIDI}-channel. The note-on/note-off commands only affect the oscillator listening on this channel. Upon recieving a note on command, the counterbase value at the input of an oscillator is latched and a counter starts counting repeatedly in this time-base. The output of the oscillator is then toggled at each counter overflow, which generates the squarewave output.

\begin{figure}[htbp]

The routing statistics generated by the TinyTapeout pipeline are listed in \autoref{tab:routing}. Especially a space utilisation of \SI{74.275}{\percent} shows, that space-optimization was crucial. Per default, the maximum density is set to \SI{60}{\percent}, which had to be adjusted to fit more features. The documentation of the TinyTapeout project stated, that a density of up to \SI{80}{\percent} worked in previous shuttles without issues. The layout as it is shown in \autoref{fig:layout} is comprised of logic cells which are predefined by the \acs{PDK}. Which logic cells are generated from the Verilog code can be seen in \autoref{tab:cells}.
